## 目标与当前状态

将当前 Seedance 视频项目整理成可复用的 AI SaaS 模板，清理旧模型页面、旧业务内容及模板遗留页面。

本次已按下方决策执行页面、内容和引用清理，并核查数据库中的指定博客与展示数据。

- 处理原则：不用的页面直接删除，不采用冷藏方案；待决定的页面在范围确认前保持原状。

- 清单初稿基于本地路由、JSON 注册、MDX 文件及 sitemap；本次执行时另核查了数据库中的指定文章和展示数据。
- slug 使用不含域名的 URL 路径；当前启用语言为英文。

## 删除单个页面：具体步骤

`3-shipany-page-builder` 创建动态页时会新增 JSON、注册 `'pages/<slug>'` 并更新 sitemap。删除时要反向处理这些内容，还要检查专用路由、MDX 和引用。以下以已删除的 `/what-is-seedance` 为示例。

1. **确认 slug 和来源。** 在项目根目录搜索 slug，并检查 `src/app/[locale]` 是否有专用路由、`content/pages` 是否有同路径 MDX；多段路径还要核对子页面是否独立注册。

   ```powershell
   rg -n -F -- 'what-is-seedance' src content public scripts
   rg --files src/app content | rg -F 'what-is-seedance'
   ```

   此示例清理前有动态页注册及英文 JSON，未发现同名专用路由或 `content/pages` MDX。其他页面可能同时有专用路由和动态页，需分别处理。

2. **删除页面专属内容。** 确认该页要删除后，在 `src/config/locale/index.ts` 的 `localeMessagesPaths` 中移除 `'pages/what-is-seedance'`，再删除 `src/config/locale/messages/en/pages/what-is-seedance.json`；检查其他语言下是否存在同 slug 文件，有则按同一范围处理。保留公共 namespace 和仍需使用的父级或子级注册项。

   ```powershell
   Remove-Item -LiteralPath 'src/config/locale/messages/en/pages/what-is-seedance.json'
   ```

   若目标还有专用路由或同路径 MDX，也要删除目标专属文件。不要删除公共的 `[...slug]`、博客 `[slug]` 兜底路由或其他页面共用的布局、组件。

3. **清理保留页面的引用。** 根据第 1 步搜索结果，移除或调整指向该 URL 的导航、页脚、按钮、正文链接和脚本引用。示例目前在英文、中文 `landing.json` 及 `pages/seedance/open-source.json` 中有链接；若后者仍保留，也需处理。不要将搜索到的资源名一律视为页面链接。

4. **更新 sitemap 和资源。** 从 `public/sitemap.xml` 中移除该 URL 对应的完整 `<url>...</url>` 项；检查图片和视频 sitemap 是否关联该页面。页面素材、组件和测试只在核对引用后按需清理或调整。

5. **处理博客等特殊来源。** 如果目标是博客文章，还需检查 `content/posts` 中同 slug 的 MDX 和语言版本、数据库已发布文章及导入脚本；根据确认范围处理。缺失文章的状态码问题见下文，不要删除共享博客路由。

6. **验证。** 再次搜索旧 slug，逐项核对剩余结果；检查变更范围。在项目根目录运行 `pnpm dev` 启动本地服务后，另开终端检查目标 URL 的 HTTP 状态，并访问保留页面。默认端口为 3000 时：

   ```powershell
   curl.exe -s -o NUL -w '%{http_code}' http://localhost:3000/what-is-seedance
   ```

   目标应返回 `404`；保留页应正常访问。完成一批后运行适用检查，全部完成后执行 `pnpm build` 和实际 HTTP 验收。未能执行的检查需记录原因。

## 执行方式与关联清理

1. 确认上述每类页面的最终删除范围；待决定的页面在确认前保持原状。
2. 检查页面来源：专用路由、`localeMessagesPaths` 中的 JSON 动态页注册、MDX 内容及数据库内容。专用路由和 JSON 并存时需同时处理。
3. 对确认删除的页面，移除对应路由、页面专用 JSON 注册和文件、相关 MDX，不保留冷藏副本。只隐藏导航入口不能代替删除，原 URL 仍可能直接访问。
4. 同步移除导航、页脚、首页及其他保留页面中的相关链接，重点检查 `messages/en/landing.json` 和 `messages/en/pages/index.json`；检查 `public/sitemap.xml`、图片 sitemap 和视频 sitemap。
5. 核对语言版本及公共文案引用；删除 `/prompts/seedance-2-0` 不连带删除待决定的 `'pages/prompts'`，图片、音乐、视频生成器共用的 `ai/*` 文案不能仅因单个页面移除而直接删除。
6. 图片、视频和组件只有在确认没有其他引用后，才作为页面专属资源清理。

JSON 路径示例：URL `/seedance/open-source` 对应注册项 `'pages/seedance/open-source'` 和 `messages/<locale>/pages/seedance/open-source.json`；注册项使用 `/`，只有运行时消息 namespace 使用 `pages.seedance.open-source`。

`scripts/test-model-landing.ts` 直接导入 `seedance-2-0.json`；若删除该 JSON，需同步调整相关测试，避免保留失效引用。

分批执行时，每批同步处理页面、相关链接和 sitemap，检查后再提交，避免留下死链接。无需等待第六类全部定案即可处理已确认页面；无需每删除一页都构建，按批完成相关检查，最终执行构建和实际 HTTP 验收。

博客详情页 `src/app/[locale]/(landing)/blog/[slug]/page.tsx` 当前在文章不存在时返回 `Post not found` 空状态组件，未调用 `notFound()`。删除文章后需验证 HTTP 状态；必要时做最小修正，确保返回真实 404。

仅移除导航或 sitemap 不算页面清理完成；还需验证动态路由或内容兜底不会让页面继续可访问。
